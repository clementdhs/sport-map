# Languages (French, English)

- `@nuxtjs/i18n` with `strategy: 'no_prefix'`: the same URL in every language. The language comes from the `sport-map-locale` cookie, else the browser, else French. `<html lang>` is the locale code (`fr`, `en`); formats use its `language` (`fr-FR`, `en-GB`) through `useFormat()`.
- Messages live in `i18n/locales/{fr,en}.json`, French being the reference: `test/unit/i18n.test.ts` fails when a key is missing or empty in a language. Plurals have two forms, `"singular | plural"` (French uses the singular for 0 and 1, see `i18n/i18n.config.ts`).
- The messages are bundled by `app/plugins/i18n-messages.ts`, which replaces the module's loader: its `/_i18n` fetch delayed hydration and broke offline follow mode.
- zod messages in `shared/utils` are translation keys, translated by `useLocalizedSchema` in forms and by `readLocalizedBody` / `getLocalizedQuery` on the server. API errors use `apiError(event, status, 'api.…')`, written in the request's language (cookie, else `Accept-Language`). Link preview images take `?lang=`, because bots send no cookie.
- A signed-in user's language is also kept in auth `user_metadata.locale` (`account-locale.client.ts`): saved when picked, applied at sign-in. Supabase writes the password reset email and its subject in it (`supabase/templates/recovery.html`, `config.toml`); the hosted project needs both pasted in the dashboard again after a change.
- e2e: the French specs cover everything; `*.en.spec.ts` replay the main flows (search, route page, creation, language picker) in projects whose browser is set to `en-GB`. The saved session holds the French cookie set while signing in: the English signed-in spec clears it.
