# Maps (MapLibre)

- MapLibre is imported only client-side (dynamic import in `onMounted`), and its worker URL is set via `?worker&url` (required by MapLibre 6 with Vite). In dev only, the console shows `ReferenceError: document is not defined` from Vite's client injected in that worker: harmless, absent from production builds.
- Map components build on `MapView` (`center`/`zoom`, or `bounds` for the first view) and add their sources and layers in its `load` event. Highlights use feature state with `promoteId`, not rebuilt data. Popups use `setText`: route names are user content.
- First view: no map locates the visitor by itself (MapLibre's position button only, on demand), so without a view of their own they open on the whole of France (`[2.35, 46.6]`, zoom 5). Start area (#147, "Ma zone de départ" in the settings, `StartAreaSettings.vue`): bounds kept in the account (`preferences.md`, cached in `sport-map:start-area`) with the name of the place picked (`SearchBox places-only`, which also emits the name; a place without bbox gets 3 km around it), or none when taken from the settings' map ("Choisir sur la carte", opening on the zone, else on the home map's last view). `useStartBounds(known)` gives the home page, /discover and the editor their first `bounds`, unless they already have a view (`routeSearch.viewKnown` / `osmDiscover.viewKnown`: shown during this visit, given by another page or a link; the editor: a track to frame). `known` is read once at setup, since the map's own first view makes it true. Bounds arriving later (the account loaded after the map, on a new device) are framed by `MapView` until the map first moves. No zone: nothing changes.
- Home map groups (#107, `RouteSearch.vue`): the results source has `cluster: true` (radius 40); only starts outside a group are a circle layer. Groups are HTML `Marker` buttons (`data-route-cluster`, label "N parcours ici, zoomer pour les voir"), synced on every `render` from `querySourceFeatures` and keyed by cluster id, count and place (an id only holds for one data set; a refetch with the same results keeps the buttons and the keyboard focus): keyboard and screen readers reach them, and they need no glyphs (the e2e style has none, so a symbol layer would fail there). A click zooms with `getClusterExpansionZoom` (labels follow a language switch) and stops its propagation (no map `click` below). The hovered route (list or map) is an HTML ring marker (`data-route-highlight`) above the groups, so it shows even when grouped: the exception to feature-state highlights, which a grouped point can't show. It has `pointer-events: none`, or under the mouse it would end the map hover that shows it.
- Testing maps in the desktop app's browser pane: MapLibre only finishes loading while the pane is visible (hidden tabs pause rendering), and tiles can take a few seconds after `[data-map-loaded]`.
- Basemaps (`app/utils/basemaps.ts`): the MapTiler style is always loaded (glyphs, sprites); Plan IGN is a raster layer added on `style.load`, above the style and below the app's layers. Picking it hides every style layer that has a source, so MapLibre requests no MapTiler tiles. The choice follows the member's account (`preferences.md`, cached in `sport-map:basemap`), picked in the "Calques" panel (below). SCAN 25 is left out: its free use (professional or associative) doesn't cover a public site. e2e tests mock `data.geopf.fr`.
- Dark basemap (#109): the MapTiler style follows the app's light or dark mode (`useColorMode`), Outdoor or Outdoor Dark (`mapStyleUrl(key, dark)`). Both have the same sources and layer ids (only colours, layer order and sprite differ), so a theme change while a map is open is a `setStyle(url, { transformStyle: keepAppLayers })` diff: it keeps the app's sources and layers, Plan IGN, the terrain and the visibility of the style's layers (hidden under Plan IGN), and costs 3 MapTiler requests (style, sprite json and png): vector tiles stay loaded, and the few relief tiles the hillshade reloads come from the browser cache (MapTiler sends `max-age` of 4 to 8 h). A diff needs a loaded style: `MapView` only switches after its first `style.load` (MapLibre 6 fires `style.load` again after a diff that changed something: `MapView` sets up the map with `once`, and records the style on screen with `on`). `data-map-dark` marks the container while the dark style is on screen; e2e mock a dark style that differs from the light one, or the diff has nothing to apply and fires nothing. Plan IGN has no dark version and stays light; the demo style (no key) has none either. Popups and MapLibre's controls follow the theme in `main.css`.
- Map controls (#104), top right: MapLibre's zoom and compass, position, then one "Calques" button (a MapLibre control filled by a `Teleport`) opening a popover, on phones too so the map stays in view: basemap, 3D switch, `MapView`'s `controls` slot (route page: track colours, `route-page.md`), and a "Légende" button opening the legend in its place (`map-legend.md`). It stays open while the map is moved (`interactOutside` prevented inside `.maplibregl-map`). Below md (`app/assets/css/main.css`) the zoom buttons are hidden (pinching zooms) and the compass only shows while the map is turned or tilted (`data-map-flat` on the container, updated on `rotate` and `pitch`), so a phone shows two buttons at rest.
- e2e runs with a fake MapTiler key (`playwright.config.ts`): `fixtures.ts` serves an empty style for `api.maptiler.com/maps/**` and no geocoding result, and tests mock their own places. `MapView` exposes `data-map-loaded`, `data-map-center` ("lng,lat") and `data-map-bearing` (whole degrees, 0 to 359), both set when the map is created and updated after each move, for tests. `start-area.spec.ts` runs with the position refused (`permissions: []`).
- 3D view (`app/utils/mapTerrain.ts`): `MapView relief` (home, route page, collection page, /discover; never the editor nor follow/record) adds a "Vue 3D (relief)" switch to the "Calques" panel, only when the style has a `raster-dem` source (MapTiler Outdoor's `terrain-rgb`; none in the demo or e2e styles). The terrain shares that source with the style's hillshade (a second source would load every elevation tile twice), exaggeration 1.5, pitch 60 (MapLibre's default maximum: the horizon stays off screen, so no sky and no far tiles). Choice kept in the account (`preferences.md`, cached in `sport-map:map-3d`), 2D by default; the cached 3D view is passed as the constructor's `pitch`, so initial bounds are framed tilted, and `style.load` or a watcher applies the account's choice when it arrives later. Under Plan IGN, the terrain still loads MapTiler elevation tiles (MapTiler quota).
- A tilted map sees ~15 times further than its centre at 60°: `mapViewState` then returns the bounds seen from above at the same centre and zoom (`flatViewBounds`), so searches (home, /discover) keep their size.
- Testing 3D: e2e use `mockReliefStyle` (fixtures, a sea-level elevation source) and never wait for `[data-map-loaded]` on a map opening in 3D: without a GPU (CI runners) the relief takes over 15 s to load, and the page stays too busy for clicks; check `[data-map-3d]` on the map container (set once the style is read and the 3D view shown) instead. In the hidden browser pane, `easeTo` doesn't animate (pitch stays 0): screenshots come from a separate headless Playwright launched with `--use-angle=swiftshader --enable-unsafe-swiftshader` (or `--use-angle=d3d11 --enable-gpu --ignore-gpu-blocklist` for the machine's GPU, needed for anything animated), signed in as the local e2e user.
